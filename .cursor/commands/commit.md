# commit

コミットメッセージを生成するコマンドです。

## 実行内容

1. ステージされている変更内容（`git diff --cached` の結果）を確認する
2. ステージ内容に基づいて適切な prefix を選択
3. プロジェクトルールに則ったコミットメッセージを生成
4. 生成したコミットメッセージを**コードブロック**で提供する
5. コミットメッセージからシェルでエラーの原因となる文字を除去
   - バッククォート（`）を除去または適切な文字に置換
   - その他シェルで問題になる可能性のある特殊文字を処理

## 制約事項

- **git コマンドは自動で実行しない**: 本コマンドはコミットメッセージの生成のみを行う。`git commit` 等の git コマンドはユーザーが手動で実行する。

## 使用方法

チャットで `/commit` と入力すると、コミットメッセージ生成フローに入ります。

## コミットメッセージのルール

プロジェクトのコミットメッセージは以下のルールに従います:

- **言語**: 日本語または英語で記述
- **prefix**: 変更の種類に応じた prefix を使用
  - `feat:` - 新機能の追加
  - `fix:` - バグ修正
  - `refactor:` - リファクタリング
  - `docs:` - ドキュメントの変更
  - `style:` - コードスタイルの変更（フォーマットなど）
  - `test:` - テストの追加・変更
  - `chore:` - ビルドプロセスやツールの変更
  - `perf:` - パフォーマンスの改善
- **タスク ID**: 関連するタスクがある場合は `[TASK-YYYYMMDD-XXX]` 形式で記載（オプション）
- **内容**: 変更内容を明確に記述
- **subject-case (commitlint)**: 1行目の subject (prefix の後の部分) は lower-case で記述する。sentence-case, start-case, pascal-case, upper-case は不可。英語で書く場合は先頭も小文字 (例: "Add" ではなく "add")。日本語のみの場合はそのままでよいが、subject に含まれる英単語は小文字にする。

## コミットメッセージの例

```
feat: ユーザーマスタ画面の一覧表示機能を追加

ユーザーマスタの画面定義書に基づいて、一覧表示機能を実装しました。
```

```
fix: 顧客マスタapiのバリデーションエラーを修正

顧客名の必須チェックが正しく動作していなかった問題を修正しました。
```

```
refactor: 代理店マスタのサービス層をリファクタリング

重複コードを削減し、可読性を向上させました。
```

## コミットメッセージのサニタイズ

生成されたコミットメッセージは、シェルでエラーの原因となる文字を自動的に除去または置換します:

- **バッククォート（`）**: 除去するか、必要に応じてシングルクォート（'）に置換
- **特殊文字**: シェルで問題になる可能性のある文字（$、`、\など）を適切に処理

これにより、`git commit -m` コマンドでエラーが発生することを防ぎます。

## 次のステップ

1. コードブロックで提供されたコミットメッセージを確認する
2. 必要に応じて修正する
3. ユーザー自身で `git commit -m "..."` を実行してコミットする（本コマンドは git コマンドを実行しない）

詳細は `.github/copilot-instructions.md` を参照してください。
